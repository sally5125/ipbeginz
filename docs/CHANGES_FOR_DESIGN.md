# IPBeginz Web — 수정 내역 (Claude Design 적용용)

기준: 디자인 번들 v.1_3 → 2026-10-01 UX 수정본. 범위는 **IP 프랜차이즈 캠페인(권한 조건 설정 · 라인 · 견적)을 제외한** 나머지 흐름.
이 문서는 Claude Design 프로젝트에 그대로 붙여 넣어 "아래 변경을 반영해 줘"라고 요청할 수 있게 화면 · 동작 단위로 적었음. 세부 근거는 `docs/analysis.md`, 정책 문장은 `docs/SPEC.md`의 "(2026-10-01)" 표기 부분.

## 한 줄 요약 (프롬프트용)

> 캠페인 만들기는 주최 프로필 유형에 맞는 흐름으로 바로 시작하고(브랜드 = 지출형 · 홍보), 게시에 필요한 항목만 기본으로 보여 주고, 게시하면 캠페인 관리 · 마켓에 즉시 나타나며 완료 박스(캠페인 보기 · 캠페인 관리 · 광고하기 선택)를 보여 준다. 지원은 캠페인이 모집하는 유형의 내 프로필로만 하고 실수령액을 보여 주며, 섭외는 내 IP · 브랜드 프로필로 "내 캠페인에 초대 / 서비스 주문" 중 하나로 보내고, 수락하면 계약이 생긴다. 승인 · 지원 상태는 캠페인별로 따로 기억하고, 상태 배지는 5계열 색만 쓴다.

## 1. 캠페인 만들기 (view = newcampaign)

| # | 위치 | Before | After |
|---|---|---|---|
| 1-1 | 진입 직후 흐름 선택 카드 | 항상 「수익형」이 선택된 채 시작. 브랜드 프로필이면 차단 팝업이 떴다가 자동으로 지출형으로 바뀌는 깜빡임 | **주최 프로필 유형이 열 수 있는 흐름이 처음부터 선택됨** — 브랜드 = 지출형, 크리에이터 · IP = 수익형. 차단 팝업 없음 |
| 1-2 | 세부 유형 카드 | 아직 고르지 않으면 목록 첫 카드(브랜드는 「IP 구매 의뢰」)가 조용히 적용되어 엉뚱한 입력 구획이 보임 | 기본 선택 = 프로필 대표 유형: **브랜드 · IP 지출형 = 홍보(마케팅)**, IP 수익형 = IP판매, 크리에이터 = 크리에이터. 해당 카드가 선택 상태로 보이고 그 구획이 바로 열림 |
| 1-3 | 흐름 드롭다운(수익형/지출형 select) | 권한 검사 없이 바뀜 | 열 수 없는 흐름을 고르면 **차단 팝업**(이유 + 「프로필 바꾸기」)이 뜨고 값은 바뀌지 않음 |
| 1-4 | 좌측 「등록 항목」 목록 | 13구획이 전부 나열(브랜드 홍보 기준) | **「필수 항목만 보기」가 기본**. 게시에 필요한 구획만 남김: 기본 정보 · 홍보 대상 · 조건 · 시딩 · 보상 · 보상 방식 · 모집 인원 · 예산 · 일정 · 검수 · 최종 확인. 목록 끝에 「＋ 선택 항목 n개 더 보기」 토글 → 펼치면 「－ 필수 항목만 보기」로 바뀜. 본문에서도 접힌 구획은 숨김(펼치면 원래 레이아웃 그대로 복원) |
| 1-5 | 상단 안내 문구 | "아래 항목을 채우고 최종 확인에서 게시합니다" | 필수 모드일 때: "게시에 필요한 항목만 보여 드립니다. 더 자세한 조건은 좌측 목록 끝 「선택 항목 더 보기」로 펼칠 수 있습니다." |
| 1-6 | 게시 시작일 | 빈 값 → 게시 시 "시작일을 골라 주세요" 토스트 | **기본값 오늘**, 게시 방식 기본 「상시」. 모집 인원 기본 10명 |
| 1-7 | 「캠페인 게시」 검증 순서 | 프로필 승인 → 보상 금액 → 대상 → 시작일 → 예치금. **제목은 검사 안 함** | ① 권한(흐름 · 세부 유형) ② **제목 필수**(없으면 토스트 + 기본 정보로 스크롤) ③ 프로필 승인 ④ 보상 금액 ⑤ **모집 인원 「무제한」이면 총예산 직접 입력 필수** ⑥ 홍보 대상 ⑦ 시작일 · 종료일 ⑧ 예치금 |
| 1-8 | 게시 직후 | 토스트만. 광고 팝업 「이 캠페인을 광고할까요?」가 자동으로 뜸. 캠페인 목록 · 마켓에는 **아무것도 추가되지 않음**(완료 메시지도 실제로는 한 번도 안 보이던 버그) | 상단 고정 액션 바 아래에 **완료 박스**(초록 바탕): ✓ "마켓에 캠페인을 게시했습니다." + 버튼 3개 `광고하기 (선택)` `캠페인 관리` `캠페인 보기`(딥퍼플 주요). 캠페인이 **캠페인 관리 · 마켓 · 프로필 캠페인 탭에 즉시** 나타남. 광고 팝업 자동 노출 제거 |
| 1-9 | 지출형 예치금 | 「무제한」 모집은 예치금을 1명분으로 계산 | 무제한이면 총예산 입력을 요구(1-7 ⑤) |

## 2. 캠페인 상세 — 지원 (view = campaign, 지출형 · 방문자)

| # | 위치 | Before | After |
|---|---|---|---|
| 2-1 | 마켓 카드 「지원하기」 | 상세로만 이동(라벨과 동작 불일치) | **상세로 이동하면서 지원 모달을 바로 연다**. 이미 지원한 캠페인은 카드 버튼이 「지원함 · 상세」 |
| 2-2 | 지원 모달 › 지원 프로필 드롭다운 | 내 크리에이터 프로필, 없으면 **모든 프로필**(IP · 브랜드 · 외부 크리에이터까지) | **캠페인이 모집하는 유형만**: 홍보 · 퀵오더 · PPL → 내 크리에이터 프로필 / 콜라보 모집 → 내 IP · 브랜드 프로필 / IP 구매 의뢰 · 사용권 신청 → 내 IP 프로필. 캠페인 소유 프로필 · 외부 프로필 제외 |
| 2-3 | 지원 모달 — 해당 프로필이 없을 때 | 아무 프로필로나 지원됨 | 드롭다운 아래 **주의 상자**(노랑): "이 캠페인은 크리에이터 프로필로만 지원할 수 있습니다. 계정에 해당 프로필이 없으니 먼저 만들어 주세요." + 「프로필 만들기」 버튼. **지원하기 버튼은 보이지 않음** |
| 2-4 | 지원 금액 | 보상이 「판매액 22%」여도 "22"가 미리 채워짐 | **원화 금액(₩…)일 때만** 미리 채움. 1,000원 미만은 "금액은 원 단위로 적어 주세요" |
| 2-5 | 지원 금액 안내문 | 제시 보상과의 차이만 | 끝에 **"· 수수료 5% 차감 후 실수령 약 ₩712,500"** 추가. 금액이 비었을 때도 "실수령액은 수수료 5%를 뺀 금액입니다" |
| 2-6 | 지원 완료 | 전역 플래그 하나 → 한 캠페인에 지원하면 **모든 지출형 캠페인**이 「지원 취소」 상태로 보임. 인박스에는 아무것도 안 생김 | **캠페인별** 지원 상태. 토스트 "○○ 프로필로 지원했습니다 · 제안 금액 ₩… — 인박스 › 보낸 요청에서 볼 수 있습니다". **인박스 › 보낸 요청 › 내 지원에 「검토 중」 행**(지원 프로필 태그 포함) 추가. 지원 취소하면 행도 사라짐 |

## 3. 섭외 · 서비스 주문 (크리에이터 카드 · 캠페인 상세 · 섭외 요청 팝업)

| # | 위치 | Before | After |
|---|---|---|---|
| 3-1 | 섭외 요청 팝업 › 프로젝트 프로필 드롭다운 | 내 프로필 전부(크리에이터 · 외부 포함) → 크리에이터를 고르면 캠페인 목록이 비어 막다른 길 | **내 IP · 브랜드 프로필만**. 없으면 "섭외를 보낼 IP · 브랜드 프로필이 없습니다" |
| 3-2 | 팝업 첫 질문 「무엇을 기준으로 제안할까요」(초대 / 서비스 주문 카드 2개) | 코드에서 꺼져 있어 항상 초대 폼만. 크리에이터 캠페인의 「이 서비스 주문」 버튼을 눌러도 초대 폼이 열림 | **두 갈래 복원**. 노출 규칙: 마켓 · 남의 캠페인에서 열고 (내 지출형 캠페인 있음 + 상대 가격표 있음)이면 두 카드 / 가격표 없으면 초대만(안내 문구) / 내 캠페인 없으면 **주문만** / 내 캠페인 상세 › 보낸 섭외에서 열면 묻지 않고 그 캠페인에 초대. 「이 서비스 주문」 버튼은 주문 폼이 미리 선택된 채 열림 |
| 3-3 | 캠페인 없음 안내 상자(빨강) | 캠페인 없으면 무조건 표시 + 보내기 비활성 | 캠페인도 가격표도 없을 때만. 주문 갈래면 보내기 활성, 라벨 「주문 요청 보내기」 |
| 3-4 | 크리에이터 서비스 캠페인 상세(소유자 본인) | 내 캠페인인데 「이 서비스 주문」 버튼이 보임 | **소유자에게는 주문 버튼 숨김** |
| 3-5 | 받은 요청 「수락」(캠페인 상세 › 받은 요청 / 인박스 › 받은 섭외) | 토스트 "계약이 만들어집니다"만, 실제 계약 없음 | **인박스 › 계약에 「캠페인 참여」 계약 행이 즉시 생김**(상대 · 금액 · 기간 · 다음 할 일 · 계약서 「캠페인 참여 계약서 (전자 동의)」). 토스트도 그렇게 안내 |
| 3-6 | 인박스 › 보낸 섭외 | 이 세션에서 보낸 것만(초기 데이터 5건 안 보임) → 캠페인 › 보낸 섭외와 숫자가 다름 | 캠페인 탭과 **같은 집합**(초기 데이터 + 새로 보낸 것). 상태 라벨: 응답 대기 / 참여 확정 / 거절 / 만료 / 취소. 「요청 취소」는 응답 대기일 때만 |
| 3-7 | 요약 문구 | "…→ 쇼케이스 등록 시 정산" | "…→ 검수 승인 시 지급" |

## 6. 죽은 버튼 · 깨진 화면

템플릿에는 있지만 동작이 없던 버튼 23개를 전부 동작하게 했고, 「마이 › 프로필 편집」 · 셀프프로모션 · 카탈로그 화면에서 비어 있던 값(아바타 이니셜 · 소개 글자 수 「N/300」 · 관심 분야 「N/5」 · 공개 범위 라벨 · 커미션 계산 「22% · 판매 1건당 ₩5,280」 등)을 채움.

| 화면 | 버튼 | 동작 |
|---|---|---|
| 마이 › 프로필 편집 | 저장 | 이름 · 아이디 검증 → 저장 토스트 → 계정 프로필로 이동 |
| | 아바타 변경 / 아바타 지우기 / 커버 변경 | 파일 선택 → 크롭 모달 → 적용 / 이니셜 아바타로 전환 / 커버 최대 3장 |
| | 링크 추가 · 공개 범위 메뉴 | 링크 행 추가(최대 10) · 전체 공개 / 팔로워 / 구독자 / 링크 공개 / 비공개 선택 |
| 캠페인 상세 › 내 지원 · 진행 | 프로모 코드 발급 / 복사 · QR 발급 / 회수 | 코드 `DC3-<핸들>-10` 표시 · 복사됨 라벨 · QR 타일 토글 |

| 공유 모달 | 링크 복사 / 닫기 | 「복사됨」 라벨 + 토스트 / 닫기 |
| 주최 프로필 피커 | 새 프로필 만들기 / 닫기 | 프로젝트 프로필 만들기(유형 선택)로 이동 / 닫기 |

## 7. 데이터(app-data.js) 정합성

- 프로필 카드의 「캠페인 n개」가 실제 캠페인 수와 일치(데몬 차일드 4 · 서하린 0 · 달빛서고 3 · 모모 1 · 루프 1 · 하늘리뷰 1)
- 하늘리뷰 = **외부 크리에이터**(`external: true`) → 지원 프로필 · 섭외 발신 · 프로필 전환 목록에서 제외, 캠페인 관리에서는 「찜 · 팔로우」
- 네온 포즈 · 스카이 포스트의 홍보 캠페인 주체 배지 「브랜드」 → **「IP」**(소유 프로필과 일치)
- 데몬 차일드 「포스터 · 아크릴 스탠드 제작」 세부 유형 「사용권 신청」(브랜드 전용) → **「퀵오더」**
- 내 지원 3건의 캠페인 제목 · 발주자를 실제 캠페인과 일치

## 8. 정책 문서(SPEC) 변경 요점

1. 캠페인 만들기는 주최 프로필 유형이 열 수 있는 흐름으로 시작, 사전 권한 검사 (9장)
2. 게시 필수값 = 제목 · 세부 유형 · (지출형) 홍보 대상 · 보상 금액 · 시작일(기본 오늘) · 프로필 승인. 무제한 모집은 총예산 필수 (9장)
3. 게시 결과: 즉시 반영 + 완료 박스. 광고 팝업 자동 노출 안 함 (9장 · 플랫폼 광고 진입점 1)
4. 지원 프로필 = 캠페인이 모집하는 유형만. 「없으면 모든 프로필」 규칙 폐기. 실수령액 표기 (지원 · 요청의 주체)
5. 섭외 발신 = 내 IP · 브랜드 프로필. 캠페인 없으면 주문만, 가격표 없으면 초대만 (집행 · 성과 확인 방법 + 섭외 · 주문 두 갈래 통합)
6. 섭외 수락 → 「캠페인 참여」 계약 즉시 생성 (9-2 섭외)
7. 승인 · 반려는 캠페인별 (9-2)
8. 소유자 / 방문자 맥락은 캠페인을 여는 쪽이 매번 정함. 소유자에게 주문 버튼 없음 (크리에이터 캠페인 상세)
9. 상태 배지 5계열 토큰 표 (10-2 신설)
10. **프로필 ≠ 캠페인** — 크리에이터도 프로젝트 프로필로 캠페인을 만든다. "프로필이 곧 캠페인(셀프 프로모션 자동 생성)" 예외 없음 (1장)
