# 프로젝트 규칙

## UI 작업 전 반드시 확인
새 화면이나 컴포넌트를 만들기 전에 **`UI 스타일 가이드.dc.html`** 을 먼저 읽고, 그 안의 글자 크기 · 색 · 간격 · 버튼/배지/칩 규칙을 그대로 적용한다. 새로운 색이나 크기를 만들지 않는다.

핵심 기준 (자세한 내용은 가이드 파일 참조):
- 페이지 헤더: 상단 카테고리 11.5px/0.14em/#8265B9 → 제목 25px/700/#27252F → 안내 문구 14px/#6F6879, 액션 버튼은 제목과 같은 줄 우측(최소 폭 82px, 보조 → 주요 순서)
- 폼: 라벨 13.5px/700/#3D3748, 필수는 라벨 뒤 빨간 `*`(「선택」 글자 금지), 안내 문구 14px/#8D8399(line-height 1.7), 입력창 13px·모서리 10px·테두리 #DAD6E1·포커스 #9276DC
- 색: 브랜드 #6846DB, 딥퍼플 #2A1F4D, 본문 #27252F / #6F6879 / #8D8399, 테두리 #E8E5ED, 배경 #FAF9FC, 성공 #3F8460, 경고 #96681A, 위험 #B0405C
- 카드: 흰 배경 · 테두리 1px #E8E5ED · 모서리 16px · 안쪽 22/24px, 카드 사이 14~16px
- 모달: 덮개 rgba(28,20,52,0.5) · 카드 모서리 20px · 폭 392(확인)/560(입력)/620~760(목록) · 제목 19px · 우상단 ✕ 32px · 버튼은 우측 정렬 보조 → 주요
- 탭·칩: 목록을 가르는 탭은 사각 칩(모서리 9px, 선택 시 #EEE8FA/#6846DB), 조건을 고르는 칩은 둥근 칩(999px, 선택 시 보라 채움). 「무관 · 전체」는 단독 선택
- 상태 배지: 진행·대기 #96681A/#FDF6E9, 완료·확정 #3F8460/#EEF7F1, 실패·거절 #B0405C/#FBEEF0, 종료·취소 #77727E/#F2F0F6 — 새 상태는 이 5계열(모집/대기/진행/실패/종료) 중 하나에 밀어 넣는다
- EARN(수익형) #E9F4EE/#3F8460 · SPEND(지출형) #F3EFFC/#5836C4, 이미지 위에는 rgba(63,132,96,.92)/rgba(104,70,219,.92) + 흰 글씨
- 금액: 통화기호 + 천 단위 쉼표, 소수점 없음, 정산·예치금은 원화 환산 기준. 들어올 돈 #3F8460 · 부족액은 −₩ 표기 #B0405C, 0원은 「무가」·「미입력」으로
- 에러·안내 상자: 실패 #FDF3F4/#F0D9E0, 주의 #FDF9F0/#EFE4CD, 안내 #F6F1FB/#E6DCF7 — 아이콘 + 한 문장 + 다음 행동
- 빈 상태는 점선 박스(1.5px dashed #E2DDEB) + "무엇이 없다 + 어떻게 채운다" 한 문장, 토스트는 딥퍼플 배경 흰 글씨
- 본문은 사이드바 ↔ 에이전트 패널 사이를 가득 채움(좌우 안쪽 여백 8px, max-width 없음). 짧은 입력은 380~620px

## 프로젝트 파일
- `IPBeginz Web.dc.html` — 실제 웹 앱 (화면 + 화면 로직)
- `app-data.js` — 앱 데이터(프로필 · 캠페인 · 카테고리 · 국가 · 템플릿). 데이터만 바뀌는 요청은 이 파일만 수정한다
- `SPEC.md` — 정책 · 필드 · 상태 규칙의 기준 문서. 결정이 바뀌면 여기를 먼저 고친다
- `CHANGELOG.md` — 작업 단위별 한 줄 기록
- `기획문서.dc.html` — 발표용 문서 (SPEC.md를 근거로 갱신)
- `IA 정보구조도.dc.html` — 화면 트리
- `UI 스타일 가이드.dc.html` — 디자인 기준
- `franchise-rights.html` — 프랜차이즈 권한 조건 설정 화면(38종 권한). 앱 안에 iframe으로 임베드됨. 권한 데이터·로직 수정은 이 파일에서, 색은 파일 끝 `#ipz-embed` 스타일 블록에서

## 편집 안전 규칙 (반드시 지킴)
- 문자 위치(인덱스) 기반 슬라이스로 파일을 자르거나 붙이지 않는다. 고유 문자열 찾기/바꾸기만 사용한다
- 큰 편집 전후로 줄 수를 대조한다. 예상 밖으로 줄어들면 즉시 중단하고 사용자에게 알린다
- 새 기능을 크게 추가하기 전에는 zip 백업을 먼저 권한다
- 정책이 바뀌는 작업은 `SPEC.md`와 `CHANGELOG.md`도 함께 갱신한다
